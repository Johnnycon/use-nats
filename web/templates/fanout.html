A platform has multiple service instances running. When a config change happens or a cache needs invalidating, a broadcast goes to ALL instances simultaneously. Unlike queue groups where one worker handles each message, here every instance must act on the broadcast. This is fire-and-forget — if an instance is down when the broadcast happens, it misses the message entirely. No retries, no persistence. (JetStream, covered in later demos, solves this.)

Note: In NATS, broadcast, fan-out, and pub/sub are all the same mechanism — nc.Publish() + nc.Subscribe(). The terms describe the same pattern from different angles. See also Demo 1 (Pub/Sub) for another example with a different real-world scenario.
