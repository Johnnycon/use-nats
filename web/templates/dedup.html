Network retries and at-least-once delivery can cause the same message to arrive twice. JetStream solves this with the Nats-Msg-Id header — if a message with the same ID arrives within the dedup window, JetStream silently drops it and returns duplicate: true in the publish ack. The original is stored once.

Try it: Click "Run Demo" to see the full flow in one click — it creates the stream, publishes a message, then re-sends the same ID so you can watch the duplicate get rejected. Click "Batch Test" to see 5 originals accepted and 5 duplicates blocked. Then hit "Replay Stream" to confirm only originals were stored.
