A task processing system needs to distribute work across multiple workers reliably. Unlike Demo 3's queue groups (fire-and-forget), a JetStream work queue guarantees each task is delivered to exactly one worker, persists unprocessed tasks if all workers are down, and redelivers tasks that aren't acknowledged in time.

Try it: Run "Setup: Work Queue" to create the stream and shared consumer. Add 2-3 workers, publish a batch of tasks, then fetch and process them. Watch how tasks are distributed across workers. Nak a task to see it get redelivered to another worker on the next fetch.
